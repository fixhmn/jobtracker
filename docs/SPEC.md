# JobTracker: спецификация первой версии

## Пользователь и доступ

Один владелец. Бот принимает команды только от `OWNER_TELEGRAM_ID`. Неизвестный пользователь не может получить, создать или изменить записи. Сначала проверяется Telegram ID, затем обрабатывается команда или callback.

Backend проверяет `X-API-Key` для всех рабочих endpoints. `/health` возвращает только статус процесса. API доступен с localhost; bot и worker обращаются к нему по внутренней сети Docker. Пользовательские ID не передаются как доверенный источник авторизации. Multi-user режим — отдельное последующее расширение.

## Данные

### applications

`id`, `company`, `position`, `url`, `location`, `salary_min`, `salary_max`, `currency`, `salary_period`, `status`, `applied_at`, `notes`, `created_at`, `updated_at`.

- Обязательны company, position и url; прочие поля опциональны.
- Зарплата: целые значения, min <= max, валюта по умолчанию USD, период annual или hourly. Не сравнивать почасовую и годовую оплату без явного преобразования.
- URL допускает только http/https. Приложение не загружает содержимое страницы.
- Повтор одинакового нормализованного URL вызывает 409 и возвращает ссылку на существующую запись. Удаляются fragment и известные tracking-параметры, но сохраняются параметры, которые могут идентифицировать вакансию.
- `applied_at` задаётся при первом переходе в Applied либо вводится вручную, если пользователь уже откликнулся. Оно не заменяется датой последующих статусов.
- Статусы: Saved, Applied, Interview, Offer, Rejected, Withdrawn.
- Можно исправлять статус в любую сторону; каждое реальное изменение попадает в историю. Повтор текущего статуса не создаёт дополнительное событие.

### status_history

`id`, `application_id`, `previous_status`, `new_status`, `changed_at`.

Создание записи и первоначальный статус фиксируются одним событием; изменение текущего статуса и запись истории выполняются в одной транзакции.

### reminders

`id`, `application_id`, `text`, `due_at`, `state`, `attempt_count`, `next_attempt_at`, `lease_until`, `delivered_at`, `completed_at`, `last_error`, `created_at`.

В реализации добавлен `lease_token`: случайный идентификатор текущего захвата. Отчёт от старого worker с истёкшим или заменённым токеном отклоняется.

- Состояния: pending, sending, sent, failed, completed, cancelled.
- Доставка и выполнение пользователем — разные события: sent не означает completed.
- В базе даты хранятся в UTC. Ввод и отображение используют `America/Chicago`, включая переходы на летнее время.
- Несуществующее местное время при переходе DST отклоняется с понятным сообщением; неоднозначное требует выбора смещения или повторного ввода.

## API

| Метод | Endpoint | Поведение |
|---|---|---|
| GET | /health | Статус процесса |
| POST | /applications | Создание, 201; дубликат — 409 |
| GET | /applications | Фильтры status, company, q; limit/offset; стабильная сортировка |
| GET | /applications/export.csv | CSV-выгрузка, фильтр status, максимум 5000 записей |
| GET | /applications/{id} | Карточка вакансии |
| PATCH | /applications/{id} | Изменение полей, включая статус |
| GET | /applications/{id}/history | История статусов |
| POST | /applications/{id}/reminders | Создание напоминания |
| GET | /reminders | Фильтры state и due_before |
| GET | /reminders/{id} | Карточка напоминания с названием компании |
| PATCH | /reminders/{id} | Изменить текст или перенести время |
| POST | /reminders/{id}/retry | Ручной повтор failed-напоминания |
| POST | /reminders/{id}/complete | Отметить выполнение |
| POST | /reminders/{id}/cancel | Отменить напоминание |
| POST | /internal/reminders/claim | Атомарно взять наступившие напоминания с временной арендой |
| POST | /internal/reminders/{id}/delivery | Зафиксировать успешную или неудачную попытку |
| GET | /stats | Статистика по from/to |

Все endpoints кроме health требуют API key. Внутренние endpoints не являются пользовательскими Telegram-командами. 404 — отсутствующая запись, 401 — отсутствующий/неправильный ключ, 422 — ошибка входных данных.

SQL-запросы параметризованы. Включены foreign keys; индексы — по status, applied_at и due_at/state. Транзакции короткие, с обработкой SQLite busy и таймаутами. Сетевые запросы никогда не выполняются внутри SQL-транзакции.

## Telegram-команды

- `/start`, `/help` — справка.
- `/new` — пошаговый ввод вакансии с возможностью пропустить необязательные поля.
- `/cancel` — отменить текущий ввод.
- `/list` — список с пагинацией и фильтром статуса.
- `/view <id>` — карточка и кнопки изменения статуса/напоминаний.
- `/search <query>` — поиск по компании и должности; первые 10 совпадений.
- `/edit <id>` — изменить компанию, должность, ссылку, локацию или заметки; `-` очищает локацию/заметки.
- `/history <id>` — последние 20 изменений статуса по времени Остина.
- `/remind <id>` — ввод даты, времени и текста.
- `/today` — невыполненные напоминания на сегодня и просроченные.
- `/done <reminder_id>` — отметить выполнение.
- `/reminders [state]` — список с пагинацией, по умолчанию только невыполненные/неотменённые.
- `/reschedule <reminder_id>` — перенести напоминание, сохранив текст.
- `/export [status]` — выгрузить отклики в CSV через приватный чат.
- `/stats` — статистика за 30 дней по умолчанию.

При недоступности backend бот отвечает понятным сообщением. Текст пользователя корректно экранируется при форматировании Telegram-сообщений.

## Доставка напоминаний

Один worker периодически получает пачку наступивших напоминаний через claim endpoint. Backend атомарно переводит их в sending и задаёт lease. После отправки worker фиксирует результат через API. Временная ошибка приводит к ограниченному числу повторных попыток с задержкой; постоянная — к failed с видимой причиной. Отмена/выполнение исключают запись из выдачи.

Истёкшая lease возвращает зависшее напоминание в очередь после падения worker. При штатной работе повторной отправки нет. Если Telegram принял сообщение, но процесс упал до фиксации результата, возможен дубль: exactly-once доставка не обещается. Эту границу надо описать в README и объяснять на интервью.

Для MVP все due напоминания отправляются по одному; отдельный утренний дайджест — последующее расширение.

Worker берёт одну запись за раз, lease действует две минуты, максимум пять попыток. API дополнительно поддерживает active/limit/offset для списка напоминаний. Отмена не отзывает сообщение, уже переданное Telegram.

Перенос допускается только в будущее для pending, sent или failed. При переносе сбрасываются предыдущая доставка, ошибка и счётчик попыток; запись возвращается в pending. Sending, completed и cancelled редактировать нельзя. Ручной retry допускается только для failed, сбрасывает попытки и ставит next_attempt_at на текущее время. Для фильтра напоминаний по вакансии предусмотрен application_id.

CSV возвращается с UTF-8 BOM для совместимости с Excel. Формулы нейтрализуются префиксом-апострофом, включая опасные префиксы после пробелов. В выгрузку не входят секреты и служебные токены доставки. Ответ помечен Cache-Control: no-store.

## Статистика

За период [from, to) показывать:

- Число откликов по applied_at.
- Число уникальных вакансий, впервые достигших Interview в этот период.
- Число уникальных вакансий, впервые достигших Offer в этот период.
- Текущее распределение записей по статусам, явно подписанное как current snapshot.

Не называть отношение интервью за период к откликам за период конверсией: это могут быть разные группы вакансий. Cohort-конверсия — отдельное расширение.

## Конфигурация

`TELEGRAM_BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `API_KEY`, `API_BASE_URL`, `DATABASE_PATH`, `TIMEZONE=America/Chicago`, `WORKER_POLL_SECONDS`.

`.env.example` содержит только заглушки. `.env`, базы SQLite и их WAL/SHM-файлы, логи и реальные пользовательские выгрузки исключаются из Git. SQLite хранится в Docker volume; только API имеет доступ к БД.
